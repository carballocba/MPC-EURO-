# Installer2-rc1 versus public GHOST v2.4.2 and the community templates

No runtime/audio/GUI/metadata/preset payload change. Public v2.4.2 assets/tag are immutable. This development candidate is local only; no maintainer response or PR change has been published.

1. **Settings boundary:** observed snapshot is separate from authoritative post-stop baseline. Require confirmed host exit and stable bytes; compare canonical plugin registrations across close, allow preference-only shutdown saves. Generate edit from the new baseline. Keep concurrent-write checks. Before own registry intent, recovery never writes settings. Afterward exact known after-image can restore exact baseline; otherwise reverse only still-known GHOST while proving foreign content unchanged.
2. **Single recovery owner:** atomic mkdir lease, atomically published boot/PID/start identity, conservative unknown-owner treatment, dead-owner takeover serialized and rechecked. Worker/guardian/manual recovery share the lease through file moves, settings restoration and service startup. Guardian waits for a live recovery child instead of overlapping it. Slow service commands are bounded; their child process identity is recorded before an execution grant, and recovery cancels orphaned control commands before touching files. Success is explicitly verified.
3. **Recovery outside discovery:** explicit validated recovery/work roots; compare against every configured content path and actual canonical aliases. Require same-filesystem work root; verified backups may be cross-filesystem. Never assume hidden Synths directories are ignored. Quota/three-slot refusal bounds accumulation. Explicit verified export-before-cleanup protects latest/incomplete recovery; no broad Synths cleanup.
4. **Stale global lock:** record boot, PID, start identity, TX and guardian. A dead owner does not mean restored files. recover.sh resolves an incomplete transaction before atomically reaping the matching dead global lock. Active/unknown owner or partially initialized ownership refuses for manual inspection. PID reuse never authorizes signaling that unrelated process.
5. **Integration/minor checks:** -y/-n/-t preserved; wrapper DEFER= declaration enables actual batched invocation, caller owns service lifecycle under -n. Production refuses test bypass variables. Root/ARM, checksummed structure, unexpected files, ownership-path traversal, symlinks/special files, writable/exec mounts, root-owned safe recovery namespaces, capacity and work filesystem are checked before shutdown. Strict supported XML subset refuses unsupported syntax rather than guessing.

Pinned community reference: sd88me/mpc-vst-plugins template and store contract inspected locally at upstream main; maintainer review PR #571 requests actual device evidence. The unmodified plugin_list.awk remains the registry editor. Custom wrappers intentionally continue to produce two catalog warnings. The field defer=true reflects actual -n behavior, not a claim of physical batch validation.

All process, service, mount, forced-termination and power/boot tests are OFFLINE mocks/local processes. Exact BusyBox configuration, shutdown saves, storage roots and physical install/update/uninstall still require owner-authorized hardware validation. No simulated run is a device PASS.
