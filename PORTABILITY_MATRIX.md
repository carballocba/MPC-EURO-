# Portability matrix

Target: original MPC One / Hakai 3.9.1 / Linux ARMv7. Research: 14 October 2026. Revisions and evidence definitions: [ECOSYSTEM_RESEARCH.md](ECOSYSTEM_RESEARCH.md). **Every CPU assessment and effort estimate is inferred; none is an MPC measurement.** Source rights do not establish binary distribution clearance for the complete VST2/host combination.

## Ranking

Ranking favors a small first proof, reusable licensed DSP, musical distinction from existing MPC ports, a separable hardware boundary and bounded resource use. Approximate effort is focused engineer-weeks for one experienced C/C++ audio developer after a suitable wrapper/build baseline exists, including basic tests/skin/state. Add roughly **1–3 weeks shared infrastructure and realtime hardening**, plus device access, licensing review and release qualification. These are planning ranges, not commitments; blocked candidates have no valid delivery estimate.

## Cross-cutting controls and timing

| Family | MIDI / tempo / transport plan | Parameter and recall needs | Main unresolved issue |
| --- | --- | --- | --- |
| Beat repeat | Trigger parameter initially; optional MIDI note and host-tempo duration; free milliseconds fallback | Duration, mix, gain, enabled; momentary trigger excluded from saved state | Zero-crossing duration differs from requested duration; half-second history prevents arbitrarily long tempo divisions. |
| Repetita / oooo / Smack | Record/capture from parameters, optional note triggers; host clock instead of GPIO gate | Varispeed, start, length, freeze/record, mix, feedback, selected channel; loop media separately from small chunk | Captured audio must persist intentionally if project recall is to reproduce performance. Do not promise it from scalar state alone. |
| _core sampler / Pikocore | MIDI note-to-slice/sample mapping proposed; host-clock policy replaces hardware clocks | Bank/sample, Break/probability, effects, pitch, sequence, seed and relative media references | _core Rack currently defers MIDI; adding VST MIDI is new work. Sample loading must occur outside audio callback. |
| Capicola | Audio transient detection; optional splice trigger; host tempo is optional, not inherent | Stretch, pitch, threshold, grain/quality, mix, feedback, source routing | Variable keyframe density and feedback can create pathological cost/output. |
| Proteus | Internal tempo-synced voice preferred; outgoing notes only through separately tested ALSA path | Scale/root, mutation, repeats, seed, sequence, oscillator parameters | Avoid process-global rand/srand and hardware wall-clock assumptions. |
| Reverb / resonators | MIDI usually unnecessary; optional freeze/gate and host-synced modulation | Mix, decay/tone/modulation/freeze, presets | Large clears, double math, denormals and initialization spikes. |

These are proposed host mappings, not evidence that Hakai routes MIDI to every effect slot. _core hardware CV and Versio GPIO controls become plugin parameters/internal modulation; no direct MPC CV-output access is assumed.

## Resource arithmetic and suitability limits

The community reference host reports Cortex-A17-class Gen1 hardware at 1.8 GHz, 44.1 kHz and 128 frames; deadline is **128 / 44100 = 2.9025 ms**. Exact user-device CPU, RAM availability, ABI, glibc and scheduler behavior remain unmeasured. Total advertised RAM is not a plugin memory budget. More cores do not automatically parallelize one DSP callback.

| Engine | Calculable storage | Interpretation |
| --- | --- | --- |
| BeatRepeat | 22,050 int16 samples = 44,100 bytes; 1,000 int16 crossing positions = 2,000 bytes; scalar state/table extra | ~46.1 KB mono, ~92.2 KB dual mono; resident memory is tiny. 0.5 s history at 44.1 kHz. |
| Wreath | Four float buffers × 48,000 × 80 = **61,440,000 bytes** | ~58.6 MiB before engine state. Allocation is global in inspected source; it must become per-instance. At host 44.1 kHz the same capacity is ~87.1 s, not exactly 80 s. |
| PlateauNEVersio | 50 × 144,000 float = **28,800,000 bytes** | ~27.5 MiB shared SDRAM pool even when fewer buffers are actually needed; poor starting memory model for multiple plugins. |
| Smack Versio | 48,000 × 150 × 2 × int16 = **28,800,000 bytes** | Ring alone; delay/reverb lanes and state add more. 44.1 kHz/ring protection changes need reference tests. |
| Capicola Versio | Two rings × 2²¹ keyframes × 12 bytes = **50,331,648 bytes** | ~48 MiB ring storage; other objects additional. This is sparse-keyframe capacity, not a fixed PCM duration. |
| _core sampler | Stereo PCM16 at 44.1 kHz = **176,400 bytes/sec** | 16 slots × 30 s = 84,672,000 bytes (~80.75 MiB), plus padding/state/FX; two banks resident during swap can exceed ~161.5 MiB. Apply a budget, not unlimited manager exports. |
| oooo | For float stereo, 352,800 bytes/sec/voice at 44.1 kHz | Six 30 s loops would be 63,504,000 bytes for one buffer each; copies, dual storage and editing peaks can add more. Actual engine allocation must be measured. |

No predicted CPU percentage is given. Fixed-point arithmetic may be efficient, but its 64-bit products, searches, control updates and render bursts still require ARM profiling. C++ float DSP can exploit ARM floating point; double math and x86-only SIMD must be checked. Desktop ports do not imply ARMv7 compatibility. Avoid blanket fast-math/unchecked NEON substitutions until reference output and worst-case behavior are characterized.

## Decision

Implement **one small, independently identified _core beat-repeat plugin first** after approval. It proves the important host, state, Q-Link, packaging and GPL source-distribution plumbing without SD parsing, a commercial Gen toolchain, tens of megabytes of loop persistence or another already-ported Mutable engine. Its mono wet behavior must be explicit; a stereo-linked algorithm is a later extension, not a promise hidden in the first port.

Keep Repetita/Wreath and the full _core desktop sampler as the next two substantive ports. Re-evaluate Capicola if granular processing takes priority, and Smack if live glitch capture takes priority. Do not begin implementation until the project owner approves the plan.
