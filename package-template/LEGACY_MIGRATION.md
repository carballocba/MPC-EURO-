# GHOST 2.4.2 installer2-rc3 legacy compatibility

No GHOST runtime payload, UID, DSP, GUI, parameter or preset byte changes.

The read-only adoption.sh classifier is used both before transaction creation and against the verified before-image during staging. It accepts only package/known-predecessor hashes, plus plugin-meta.xml byte-identical to the shipped template with this exact canonical Synths path expanded. The known desktop mpc-plugin.json is pinned in legacy-owned.sha256; arbitrary metadata edits, different identities/paths and unknown runtime replacements still refuse. An installed ownership manifest must exactly match a shipped recognized manifest; it cannot claim arbitrary user files.

All existing files under Presets/, Preset Library/ and Performance Presets/, including indexes and all52 FXP, remain untouched during install/update/uninstall. Unknown files outside those folders remain copied in the stage. Existing file/directory collisions refuse; no unknown content is overwritten. Uninstall leaves retained preset/user data in the original directory, removes recognized package runtime and its generated ownership record, and removes only GHOST's registry entry. Reinstall reuses the retained presets. Modified package runtime refuses before host stop.

The desktop predecessor has366 regular files, no ownership record, valid expanded plugin-meta.xml, and two older descriptive fields in mpc-plugin.json. rc3 writes the same366-file community payload, preserves existing presets and adds .ghost-owned.sha256. Package-owned non-preset files can become root-owned according to the uploaded package; user/preset file metadata is retained by cp-a. Verified backups preserve original numeric ownership/modes for rollback. There is no execute-bit requirement for a readable shared library; noexec mounts remain rejected. The package metadata template may remain unexpanded on disk as in the community package; only its registry entry is expanded to the actual target. Both representations are recognized on subsequent adoption.

Recovery retains at most3 transaction slots/512MiB. A previous aborted packet still occupies a slot and is not auto-deleted. For a full install/update/uninstall trial when such a packet exists, after the first successful install explicitly export/verify that older completed packet using its cleanup.sh before subsequent transactions. Retain its independent export and Mac copy. Never clean the newest or an incomplete packet, bypass quotas or delete the only recoverable copy. This export requires owner authorization; the dry run never performs it.

The classifier and registry predictions have been exercised read-only on the real MPC filesystem. No rc3 installation/update/uninstall, service restart or musical test is implied. Those require explicit supervised authorization.
