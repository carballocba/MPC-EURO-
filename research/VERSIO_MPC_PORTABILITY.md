# Practical MPC portability

Target: original MPC One, Hakai 3.9.1, Linux ARMv7. Research: 14 October 2026. **No candidate was compiled, run or measured here.** Source facts are pinned through [the catalog](VERSIO_PHASE2_CATALOG.md); effort/CPU suitability and host mappings below are estimates or proposals. Permission gates take precedence over technical convenience.

## Host baseline and common infrastructure

The [current MPC kit](https://github.com/sd88me/mpc-vst-plugins/tree/ce6278d53091ba40127838020fc8a7887894551f) and [hardware notes](https://github.com/sd88me/mpc-vst-plugins/blob/ce6278d53091ba40127838020fc8a7887894551f/docs/NOTES.md) report Gen1 armhf/ARMv7, 44.1 kHz, 128 frames, host tempo/PPQ, chunks and native skins. At those settings the callback deadline is **2.9025 ms**. Community measurements are mostly Force, with some Live/One reports; **none certifies the user's exact Hakai 3.9.1 One**. CPU, libc/ABI, settings/content paths, scheduler, mount flags, event routing and device-specific Q-Link banking still need approved hardware validation.

Source-verified kit limitations remain:

- Engine calls use a per-instance pthread mutex, including process/render. Keep correctness with audio-owned state and bounded parameter/event handoff rather than simply removing locks.
- Effects pass through interleaved int16. Appropriate for some fixed-point DSP, but unnecessary quantization for native-float effects and the dry path. Prefer a reviewed float-engine path for Wreath/Capicola/Resilio/Plateau.
- Rate/block/mains-change dispatchers return success without actually adapting DSP. Record negotiated configuration and prepare safely off audio; no silent 48/32 kHz DSP at 44.1 kHz.
- State uses an 8 KiB char chunk. Save versioned validated fields; don't serialize raw C structs/pointers or large loop PCM there.
- Instrument sample-accurate event splitting is optional; effects don't get that option automatically. Momentary parameter triggers must work even if Hakai doesn't deliver MIDI to an insert slot.

Reuse pinned SDK-free ABI, skin/Q-Link generation, metadata, test and packaging implementations; do not start a large JUCE runtime merely to host lightweight DSP. Build proposal is armhf with an old-glibc-compatible toolchain, as the community kit uses; inspect ELF32/ARM/float ABI, exports and symbol dependencies before qualification. x86 or QEMU correctness is not target CPU evidence. All code/installation work remains future, separately approved.

### Source findings that change scope

**Resilio:** its [NOTICE](https://github.com/jeffebauer/resilio-versio/blob/2ab71a9be56b765bbc2f666527e44cfc278a511e/NOTICE) allows separating the MIT core from the JUCE/AGPL desktop wrapper. setHostTempo, sample-offset clock/gate/button and parameter table already exist. A narrow adapter is preferable to replacing the DSP. The header's memoryBytes method reports object+pool and does not include all separate tape memory; don't quote it as total RSS. Coefficient redesign/control transitions must be profiled alongside audio.

**Hillside:** current code selects 48 kHz/256 while documentation describes96k and8×9.4s. Keeping900,000 samples at48k gives18.75s per slot, not9.4s. Timing helpers still contain96k-derived constants. This is a **source/documentation discrepancy**, not a measured hardware defect or permission to “fix” source during research. Pick a release pin and reconcile units before planning a port.

**Acidus:** source/MIDI infrastructure already exists in Open303, but dynamic std::list note management is not realtime-safe by construction. Accent at velocity≥100 and overlapping-note slide semantics are visible in the core; Babyfish envelope retrigger/range differences live in the Versio wrapper. ADC calibration and QSPI settings disappear in a MIDI plugin. Existing MPC Open303's GPL additions and tested.json Live II reports are reference evidence, not a MIT umbrella or a One/Hakai certificate.

**Multi:** actual source contains LO-FI processing with RMS envelope, filters, saturation/compression-related state and time-varying modulation, plus loop/delay/spectral modes. Its main integration is tightly coupled to globals/LEDs/control polling. Individual stmlib-derived MIT headers are reusable under their terms, but the complete Paolo source has no established binary grant. Do not turn permission for a header into permission for the whole effect.

## Timing, controls and persistence policies

**Tempo/transport:** verify audioMasterGetTime flags; use valid BPM/PPQ and sample offsets, with free-time fallback. Firmware gate inputs may represent beat,24PPQN or irregular trigger intervals—keep those distinct. Define restart/seek/loop/stop behavior. Resilio host-tempo API offers a direct reuse path; Wreath's new quantization would be adapter work. WTF!'s interval inference remains unknown; Smack has24PPQN assumptions.

**MIDI/Q-Links:** map gate/record/capture to stable parameters first; optional note input only after effect-slot routing proof. Names/ranges/enum values and parameter indices are stable and append-only. Use an independent one-page/page-bank skin with original assets; test four-knob MPC One banking rather than Force geometry. Smooth length/filter/gain where musically appropriate; bound command processing and retain release/all-notes-off under overload.

**MIDI output/CV:** community notes report normal VST MIDI output is ignored, with an ALSA sequencer-port workaround tested on Force. Prefer internal sound/sequence initially. Physical MPC CV/Gate access is **not verified**. A later separately approved MIDI→native CV track or external MIDI-to-CV test could explore it; no raw device writes or undocumented CV API in the baseline.

**Preset/project recall:** distinguish parameters/seed from recorded audio/tails/play phase. BeatRepeat intentionally resets transient history. Resilio/ordinary reverbs can save scalar sound state without embedding tails. Repetita/Smack/Hillside/Multi microloop need worker-backed, versioned media storage if captured performances must reopen faithfully. VST2 may not expose a project directory; relative-media/relink strategy is unverified. No file writes/export/deallocation on audio; no dumping raw structs into chunks. Momentary record/capture/throw is never restored held.

**Packaging:** unique plugin UID/name/vendor, .so, manifest metadata, native version.xml/TUI/Q-Links, separate directory and source/NOTICE/checksums. Existing Hakai/community registration typically changes MPC.settings and may restart the host. This task authorizes neither. Future deployment requires a non-conflicting reviewed package and separate approval. No default-branch change, overwriting existing plugins or other-repo dependency.

## Validation required after explicit coding approval

Use pinned original DSP/reference fixtures, meaningful state/output comparisons, boundary/event tests, silence/impulse/stereo music, malformed chunks, allocation failure, multiple instances and source/performance control transitions. Native sanitizer tests and ARM/QEMU checks can establish software correctness; actual One/Hakai tests must establish host load, Q-Link/touch/automation, transport/recall and real worst-case CPU/RSS.

Profile **worst callback**, not only average: long clears, clock/capture search, dense keyframes, reverb redesign, note-list activity and sample-bank loads. Community budget guidance (p99≤15%, worst≤50% of one block) is a proposed comfort threshold, not a measured result. Thread-CPU-only timing can hide waiting/preemption/worker cost; use callback/wall-time and worker utilization in a real project too.

No test command was run in Phase 2, and no firmware, plugin or runtime was built. Licensing, naming and VST2 binary distribution review remain release gates even after software tests pass.
